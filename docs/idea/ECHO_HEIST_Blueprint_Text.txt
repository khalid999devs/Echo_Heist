01 / NARRATIVE SPECIFICATION


Story, narrative and mission beats
The entire story is delivered within one 10-20 minute successful run; dialogue is short, readable, and optional to skip.



  Premise and cast

NEXUS is the facility supervisory intelligence, a voice on displays and alarms rather than a boss that physically fights. It
commandeered a high-security energy-research facility and sealed away an unstable experimental energy core. The
intruder - either a human operative or an autonomous companion robot - must retrieve the core and exit through the
original entry/extraction zone. Sentinels, Trackers and an Interceptor are its physical security agents.

02 / LEVEL SPECIFICATION


Level topology and navigation design
Use one connected Tiled map with two meaningful paths to and from the core; keep all routes physically readable.



  Canonical five-zone layout



                                                              SECURITY
                                                              CONTROL

  ENTRY                       SERVICE                                                            CORE
  EXTRACTION                  WING                                                               CHAMBER

                                                              RESEARCH
                                                              FLOOR



Map topology: Entry/Extraction connects to Service Wing; Service Wing branches into Security Control (upper) and Research
Floor (lower); both reconnect near the Core Chamber. Add at least one narrow cross-link between the branches, gated only by
patrol timing or simple door interaction, not a permanently locked puzzle.


  Map implementation defaults - tune by playtest

 PROPERTY                          STARTING VALUE / RULE

 Coordinate model                  32 px logical collision tile; sample layout ~80 x 56 cells, camera follows operative. These are design
                                   starting points, not a fixed production map.

 Navigation                        4-neighbor, unit tile moves for BFS/A* graph; guard sprites smoothly interpolate between cell
                                   centers. No diagonal corner-cutting.

 Connectivity                      Every walkable navigation cell reachable from at least one valid branch; both branches allow return
                                   to extraction after lockdown.

 Guard roster                      2-3 Sentinels, 1-2 Trackers, 1 Interceptor = roughly 5-6 physical units. NEXUS is nonphysical.

 Route character                   Security Control: shorter, exposed sightlines, chokepoints. Research Floor: longer, noisy props, more
                                   cover.

 Objective anchors                 SPAWN/EXIT and CORE_PLINTH typed map objects. They do not relocate between modes.



  Essential world entities

Walls (opaque and collidable); glass partitions (visibility and sound rules explicitly tagged); cover obstacles; marked hiding
cabinets; doors and controlled passages; core plinth; exit; glass equipment rack; loose rolling canister; patrol waypoints;
navigation sectors and tactical chokepoints; lighting overlays and security screens.



     NO FAKE DIFFICULTY
   Create meaningful route tradeoffs, not unavoidable traps. A cautious intruder must always have at least one navigable path
   to the core and, during lockdown, back to extraction. A guard predicting a chokepoint should be a challenge, not a
   guaranteed softlock.

05 / STATE MACHINE + SENSING


Stealth, suspicion, detection and capture
Separate "something happened" from "I have identified the intruder." Discovery creates pursuit, not automatic defeat.



  Detection states and transitions

 STATE                          ENTRY CONDITION                                         BEHAVIOR / EXIT

 PATROL                         Default: nothing relevant observed.                     Follow route; respond to sight and sound.

 SUSPICIOUS                     Audible event, weak visual glimpse or unclear cue.      Turn/search toward cue; retain source with TTL. Sound
                                                                                        alone never reports confirmed position.

 SPOTTED                        Line of sight to actual intruder, identification        Show readable confirmation meter; hiding or cover
                                progress increasing.                                    may interrupt before full confirmation.

 DISCOVERED / CHASE             Identification threshold reached; near face-to-face     Transmit sighting with timestamp; pursue last known
                                confirms rapidly.                                       actual position.

 SEARCH                         LOS lost and chase reached last-known point.            Inspect plausible neighbor locations, then expire old
                                                                                        report.

 CAPTURE WIND-UP                Guard adjacent with valid contact and line of reach.    ~0.4 s telegraphed grab; successful interrupt/escape
                                                                                        cancels. Completed grab ends run.

 RETURN / LOCKDOWN              Search expires; or global core alarm triggers.          Restore patrol or move to defensible post while
                                                                                        preserving fairness.



  Sensing rules, timing defaults

   Sight: cone angle and range differ by guard type; raycast grid walls / tagged solid occluders. Detection rises only while
   actual intruder is visibly identified.

   Sound: NoiseEvent(position, radius, kind, tick) notifies only guards in acoustic reach; path occlusion may reduce range.
   Investigate source, not actor coordinates.

   Fuzzy suspicion produces investigation urgency from hearing and partial visibility; confirmed identity additionally needs
   actual line of sight.

   Memory: record last actual sighting and its age; old locations lose confidence. Reports carry a source, sector, observed
   position and timestamp.

   Hiding: explicit cabinet/cove sets concealment when not currently witnessed; a guard seeing entry can search that specific
   hide spot.


  Failure, alert and pressure - separate concepts


  RECOVERABLE DISCOVERY                                                      MANDATORY PLOT EVENT


  LOCAL SECURITY ALERT                                                       GLOBAL CORE LOCKDOWN
  Any confirmed pre-theft sighting can cause pursuit and                     Atomic CORE_TAKEN event guarantees facility-wide red
  local investigation. When contact is lost, search can cool                 alert and revised patrol assignments. Never equate this
  down; it does not trigger permanent lockdown.                              with defeat or close off every escape route.




     EXACT WIN / LOSE CONTRACT
   WIN requires possession of the energy core and reaching the Entry extraction trigger. LOSS occurs only after a robot
   completes capture, or on voluntary abort. Being spotted, surrounded, noisy, out of gadgets, or in lockdown is not by itself

  NoiseEvent and investigation example


   SOUND SYSTEM CONTRACT
   NoiseEvent {id, kind, tile, radius_tiles, tick, source_visible?}
   create(event): if sound is gameplay-relevant, enqueue once
   for each guard: hear(event) iff acoustic_distance <= radius
   heard_guard.memory.last_noise = event.tile; state = INVESTIGATE
   # hearing reveals the noisy tile, NOT the intruder's hidden tile


Suggested radii: walk 0-1, sprint 3, rolling canister 4, glass break 6, melee 6, EMP 5 tiles. These are balance defaults; visual
sound ripples should match the actual detection radii. Guards may hear multiple events and prefer stronger/recent cues, but
never invent the cause.


  Collision, interaction and replay safety

   Treat movement as collision queries against physics layers; use swept or substepped collision to avoid tunneling at sprint
   speed.

   Tag all interactables with stable IDs and persistent per-run state. Glass cannot "break twice" or emit duplicate alarms per
   overlap frame.

   Resolve interaction priority deterministically: closest valid object, tie-break by ID. Show an "E - Interact" hint on eligible
   objects.

   Echo decoy is an illusion object, not a second physical operative. It may attract sight but must never steal the core or
   trigger exit.

Every emergency response buys time at a cost. Stealth is always the primary way to win.

  Behavior precedence and anti-exploit

   A disabled/stunned guard cannot start or complete capture; cancel an in-progress grab if stun lands before capture
   resolves.

   After recovering from melee, a short stun immunity window (suggested ~2 s) stops infinite stunlock loops. Hitting it again
   still emits noise.

   Echo deception must be plausible: a Sentinel checks unusual motion via normal sight and may investigate the ghost
   location; the ghost is not guaranteed to fool every observer.

   Do not let melee eliminate robots, EMP recharge at checkpoints, or gadgets solve every encounter. Resource discipline
   affects scores, not simple normal gadget use.


  Encounter example: recoverable crisis

At a narrow Research Corridor corner, the Tracker confirms the intruder. The intruder can turn back, retreat behind a rack,
use one Echo, stun the Tracker at close range, or spend the EMP. Melee makes a clang audible to a Sentinel in the next
room. If the intruder escapes line of sight, pursuit shifts into a last-seen-location search instead of magically tracking its new
route.


     BALANCE PRINCIPLE
   First completion should feel earned; a cautious route exists, mistakes may be recovered from, and S rank is significantly
   harder. Test for "fair but tense": no unavoidable capture on a blind corner, no all-powerful EMP, and no route that needs
   perfect reflexes.

08 / DEFENDER INTELLIGENCE - TYPE A


Sentinel: BFS, FSM and fuzzy suspicion
The Sentinel is a reliable patrol guard, not omniscient; fuzzy inference grades uncertainty and the FSM decides behavior.



  Finite-state machine and patrol strategy


  01                          02                              03                      04                            05
 PATROL                       INVESTIGATE                     SPOTTED                 CHASE / SEARCH                RETURN
 BFS to waypoint              last noise                      visual check            last known cell               BFS home



Patrol uses BFS on the static unweighted 4-connected occupancy graph. Recompute after blocked doors or large detours, not
every render frame. Patrol route and home waypoint are per-guard data. A high-confidence confirmed sighting triggers CHASE;
otherwise hears, scans, and returns after investigation timeout.


  Fuzzy Logic design - prototype inference

 INPUT                               FUZZY SETS / EXAMPLE                    EFFECT

 Visibility of cue                   none / partial / clear                  A partial glimpse raises suspicion but is not identity
                                                                             confirmation.

 Distance                            near / medium / far                     Closer uncertain cues should be investigated sooner.

 Sound salience                      quiet / notable / loud                  Loud events justify investigation even with zero LOS.


Use triangular/trapezoidal memberships in [0,1]. For an initial zero-order Sugeno model, compute each rule firing as
min(input memberships), then weighted-average singleton outputs. Example output is an investigation urgency value in [0,1];
use it to vary turn speed, approach urgency and SUSPICIOUS threshold. Keep the separate visual identification meter
authoritative for confirmed detection.

 FUZZY RULE                                                                                                              URGENCY

 IF sound is loud AND distance is near, THEN investigate very strongly                                                   0.95

 IF partial vision AND distance is near, THEN investigate strongly                                                       0.80

 IF sound is notable AND distance is far, THEN investigate moderately                                                    0.45

 IF no sight AND quiet sound, THEN maintain routine or weakly inspect                                                    0.10



   FUZZY --> FSM BRIDGE
   w_i = min(mu_visibility_i, mu_distance_i, mu_sound_i)
   urgency = sum(w_i * output_i) / max(epsilon, sum(w_i))
   if actual_visible_intruder: update_identification_meter(dt)
   elif urgency >= investigate_threshold: investigate(cue_tile)
   # sound/decoy only: NEVER fabricate confirmed intruder position




       DEMO / TESTABLE BEHAVIOR
   A glass break behind the wall causes investigation but not confirmed detection. A brief partial glimpse causes a slow
   orientation response. Sustained close sight confirms rapidly. Log memberships, rule activations, urgency and FSM state for
   Lab View.

09 / DEFENDER INTELLIGENCE - TYPES B AND C


Tracker and Interceptor algorithms
The Tracker reacts to evidence; the Interceptor makes uncertain adversarial predictions over a small route graph.



  Tracker - heuristic A* + last-seen memory

The Tracker receives actual sightings and legitimate radio reports. When it sees the intruder, it A*-plans toward the visible tile.
Once LOS breaks, it goes to its stored last-known location, inspects a few nearby feasible tiles, then returns when memory
expires. Proposed memory TTL: ~5 s after last direct visual contact, extend only on fresh reports.


   A* AND LIMITED MEMORY
   g(start)=0; h(n)=abs(nx-gx)+abs(ny-gy)
   f(n)=g(n)+h(n)                        # unit-cost Manhattan heuristic
   if observed-danger routing: g += nonnegative exposure_penalty
   on_los: remember(real_intruder_tile, now); state=CHASE
   on_los_lost: pathfind(memory.tile); state=SEARCH
   on_ttl_elapsed: lower confidence; state=RETURN


Correctness: With 4-neighbor unit movement and nonnegative danger penalties, Manhattan x minimum-step-cost remains
admissible. Never use unobserved intruder coordinates as an A* goal. Search for plausible neighbors rather than marching to the
intruder through walls.


  Interceptor - bounded minimax + alpha-beta pruning

The Interceptor defends route-level chokepoints (Security Junction, Service Access, Research Return), not individual pixel
positions. At a major sighting or lockdown, it considers 2-3 plausible intruder routes consistent with last-known evidence,
compares possible block locations, and chooses a move minimizing the intruder's escape advantage. An incorrect hypothesis
can lead it to the wrong post.

 COMPONENT                        DESIGN

 State abstraction                Small graph of sector gates, safe branches, core and extraction; annotate guard travel time.

 Players in search                Intruder chooses plausible branch; Interceptor chooses block/post; alternate as adversarial choices.

 Evaluation                       Prefer blocking likely exit/quick routes; punish slow unreachable intercepts and leaving all gates
                                  unguarded.

 Search budget                    Depth 2-3 initially; alpha-beta prunes dominated branches. Run on meaningful new reports, not every
                                  frame.

 Fairness                         Opponent intent is an estimated distribution, not hidden real future action. Guard must physically travel
                                  to chosen post.



   INTERCEPTOR DECISION
   choose_post(reports):
     candidate_routes = infer_plausible_routes(reports)
     best_post = alphabeta(route_graph, depth=3, hypotheses=candidate_routes)
     return a_star_route_to(best_post)       # physical movement, no teleport

  Mission FSM and strategic choices

 INFILTRATE                        REACH CORE              TAKE CORE                     RETURN / EXTRACT               WIN or CAPTURE




A single CompanionController chooses actions. The FSM defines phase and legal goal; utility logic handles immediate danger
(break line of sight, interrupt a grab, conserve gadgets when safe); strategic MCTS selects among plans at important events;
danger-aware heuristic A* converts the selected target into a traversable path. Every frame is not an expensive strategic
search.

 UTILITY FEATURE                                EXAMPLE WEIGHT / POLICY EFFECT

 Threat / line-of-sight exposure                Cautious strategy assigns high penalty to exposed tiles and confirmed threat arcs.

 Elapsed time / path length                     Bold/Rush strategy cares more about distance and fast extraction.

 Gadget scarcity                                EMP is reserved for capture threats; Echo for plausible distractions.

 Uncertainty / stale memory                     Old sightings become hypotheses with declining confidence, not hard obstacles.

 Mode fairness                                  Same legal Action set, speed, collision rules and gadget stock as human operative.



  Danger-aware A*


   COMPANION NAVIGATION MODEL
   path_cost(edge) = travel_cost + risk_weight * seen_risk(edge)
   h(n) = Manhattan(n, target) * minimum_positive_step_cost
   # only OBSERVED or conservatively inferred danger in seen_risk
   # never query WorldState.hidden_guard_position()
   replan when: guard observed, route blocked, new mission phase,
                   MCTS changes tactical objective, or current path unsafe




      IMPORTANT: NO AUTOMATIC TRAINING IN V1
   The companion reasons from a built-in ruleset on the first attempt. You improve policies between attempts in the
   Workshop; it does not retrain a neural network or automatically change its own persistent policy.

12 / MONTE CARLO TREE SEARCH DESIGN


Companion MCTS: a real bounded search
Apply MCTS to choices at junctions or alert events, not to every pixel of movement.



  Search model and action space

A tactical state contains current zone, subgoal, resource counts, fresh sightings, coarse alert level, candidate passages, and
whether the core is carried. Legal actions: advance, wait, hide, take alternate route, deploy Echo, retreat; add EMP or
melee only when range and inventory make them legal. MCTS uses a small abstract facility graph and a belief model built
from allowed observations.

 MCTS STAGE                        V1 BEHAVIOR

 Selection                         UCT: exploit estimated value plus exploration term c * sqrt(ln(parent visits) / child visits).

 Expansion                         Add one legal strategic response not tried from the chosen node.

 Rollout                           Simulate short 3-4 tactical transitions using approximate guard rules; unknown guards are sampled
                                   from plausible hypotheses, not actual hidden positions.

 Backpropagation                   Propagate normalized reward to the selected branch; retain visits and mean return.

 Execution                         Choose a high-visit action, then use utility overrides and heuristic A* to execute it physically.



  Decision budget and reward (proposed defaults)

Start with 64 simulations per major decision, max depth 4 abstract moves; trigger on new sighting, route junction,
objective transition or inability to progress. Avoid time-based nondeterministic search stops for comparable fixed-seed tests.
Normalized trial reward: +100 extraction, +30 progress toward next objective, -100 capture, -25 confirmed detection, -5
gadget cost, -small time cost; policy weights re-scale the risk/time terms.


   MCTS STRATEGIC PLANNER
   def strategic_mcts(observation, policy, seed):
       root = make_belief_state(observation)         # never real hidden guards
       for i in range(policy.simulations):         # e.g. 64
             node = select_uct(root); child = expand_legal(node)
             value = rollout_model(child, depth=4, rng=seeded_rng)
             backpropagate(child, value)
       return max(root.children, key=lambda a: a.visits).action




  Proof of real MCTS use

   Display chosen action, visit counts and mean rewards for at least three alternatives in AI Lab View.

   Unit test legal action filtering, backpropagation changes to visits, fixed-seed repeatability and preference shifts from
   Workshop weights.

   Fallback if action becomes illegal due to a changed world state: retreat/wait safely, re-observe and re-plan.

15 / SYSTEMS DESIGN


Engineering architecture and state machine
Separate the deterministic simulation from rendering so AI experiments can run headlessly and real-time gameplay can
share identical rules.



  Runtime pipeline


  01                        02                            03                             04                             05
 WorldState                 Filter observations          Human or AI                     Fixed simulation               Event log + render
                                                         Actions                         step



A top-level GameController manages MENU / MODE / WORKSHOP / PLAY / RESULT / EPILOGUE. The headless Simulation owns
physics, entity inventories, guard vision, noise, mission progress, alarms, score and win/fail evaluation. Pygame handles input,
presentation, animation and audio. Controllers return structured actions; no controller can mutate the world directly.


  Recommended Python package boundaries

 DIRECTORY                             OWNERSHIP

 game/core/                            WorldState, entities, collision, fixed_tick, events, observation filters, action validation, mission FSM,
                                       scoring.

 game/level/                           Tiled JSON importer, object layers, navigation grid, LOS occlusion, sector/chokepoint graph, path
                                       caches.

 game/ai/                              BFS, A*, fuzzy, memory, guards, alpha-beta, MCTS, NEXUS director, companion controller and
                                       beliefs.

 game/workshop/                        Policy enums, presets, validation, profile save/load, run comparison.

 game/ui/                              Main menu, modes, workshop, HUD, result reports, Lab View, accessibility, camera and animation.

 assets/ + data/                       Textures, sprite atlases, SFX/music, Tiled maps, dialogue and default config.

 tests/ + scripts/                     Unit/integration tests, fixed-seed experiments, benchmark runner and platform packaging.



  Deterministic tick order - all gameplay is resolved here


   FIXED-TICK UPDATE CONTRACT
   1. Read queued player input / AI choice from last Observation
   2. Validate legality and resources; resolve movement + collisions
   3. Execute interaction/ability actions; emit NoiseEvent/CORE_TAKEN
   4. Update sensors (sight, acoustic reach) and memory
   5. Update NEXUS orders, guard FSM and capture wind-ups
   6. Evaluate global alert, mission win/loss, rank; append JSONL log
   7. Render the committed state; deliver next filtered Observation




       FAIRNESS / CODE REVIEW RULE
   AI controllers receive immutable typed Observation objects; only Simulation has authoritative WorldState. MCTS rollout uses a
   copy of the agent belief state, not a hidden clone of the real world. Make tests fail if controllers access forbidden fields.
